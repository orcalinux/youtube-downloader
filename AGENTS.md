# AGENTS.md — YouTube Downloader

## Quick start

```bash
make install      # create .venv + install deps (run once)
make check_ffmpeg # install ffmpeg system-wide if missing
make run          # deps + ffmpeg check + launch app
make docker-run   # build + run in Docker (binds ~/Downloads)
make clean        # wipe .venv, logs, docker image
make deps-update  # regenerate requirements.in → requirements.txt
```

Or directly: `.venv/bin/python main.py`

## Project layout

- `main.py` — entrypoint, interactive loop
- `config.py` — quality presets, logging config (runs at import time)
- `downloader.py` — yt-dlp wrapper (download_video, fetch_playlist_videos, download_videos)
- `utils.py` — Rich/prompt_toolkit interactive prompts, URL validation
- `requirements.in` — direct dependencies (edit this)
- `requirements.txt` — pinned full tree (generated by pip-compile)

Dependency flow: `config ← main ← {downloader, utils}`

## Key facts

- Uses **yt-dlp** (not youtube_dl or pytube). ffmpeg required for merging best-quality streams.
- **deno JS runtime** is required by yt-dlp for full extraction (33 formats vs 27 without). `make run` and `make docker-run` both handle this automatically.
- `remote_components: {'ejs:github'}` is set in `downloader.py` — yt-dlp downloads challenge-solver scripts from GitHub on first run (cached afterward).
- Interactive CLI via Rich + prompt_toolkit (tab-completion for directories).
- Logging to both `downloader.log` and stdout — configured in `config.py` at import.
- `requirements.in` is the source of truth; `requirements.txt` is pinned via `pip-compile`. Edit `.in` then run `make deps-update`.
- yt-dlp is loosely pinned (`>=`) because YouTube breaks often — upgrade whenever downloads fail.
- No test suite, no lint/typecheck, no CI.

## Docker

```bash
make docker-run                # HOST_DIR defaults to ~/Downloads
HOST_DIR=/path make docker-run # override
```

Bare Docker: `docker run -it --rm -v ~/Downloads:/root/Downloads youtube-downloader`

Container runs as `root`. deno is pre-installed and challenge-solver scripts are pre-cached in the image.

## Conventions (repo-specific)

- Use Rich markup (`[bold red]...[/bold red]`) for console output, not raw `print()`.
- All user-facing prompts route through `safe_prompt()` (utils.py) for clean Ctrl+C handling — never call `Prompt.ask()` directly.
- yt-dlp format selectors in `config.py:VIDEO_QUALITIES`.
